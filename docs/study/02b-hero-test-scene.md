# Hero test scene (scratch)

A playable scratch scene for judging the hero's ground and air movement by hand. It is generated by code, uses only plain coloured squares (no game art), and touches neither SampleScene nor any prototype asset.

## Opening and playing

1. Menu **Hollowknight > Silksong > Build Hero Test Scene** (re-run any time; it rebuilds `Assets/Scenes/SilksongHero.unity` and creates `Assets/Silksong/Hero/HeroConfig.asset` only if it is missing, so tuned values are never overwritten).
2. Press Play. The hero is the yellow rectangle; the green pole marks the start.
3. Batch/CI build: `Unity.exe -batchmode -nographics -projectPath <project> -executeMethod Hollowknight.Silksong.Editor.HeroTestSceneBuilder.BuildBatch -quit -logFile build.log`

The hero ignores the project's Physics2D gravity: the controller sets its gravity scale to zero and applies `HeroConfig.Gravity` itself, so only the config matters.

## Controls

| Action | Keyboard | Gamepad |
|---|---|---|
| Move | Arrows (also WASD) | Stick / d-pad |
| Jump (hold for height) | Z (also Space) | South button |
| Attack | X (stub, logs only) | per input asset |
| Dash | C (stub, logs only) | per input asset |
| Return to start | R | n/a |
| Hide or show debug panel | F1 | n/a |

The overlay shows State, Velocity, IsGrounded, facing, the apex height of the last jump above its takeoff point, and the main config values.

## What each part is for

Heights below are measured from the floor the hero stands on.

- **Start / wide upper floor** (x from -20 to 40): run both ways, check run speed, stopping and turning.
- **Ledge** (x = 40): walk off and press jump a moment late. Coyote time (0.08 s) should still allow the jump; much later should not.
- **Lower floor** (5 units down): fall and landing; the fall speed cap. The cliff back up is 5 units, so a full held jump should climb it.
- **30 degree slope** and **45 degree slope** (each rises 5 units to a plateau level with the upper floor): walk up and down; stand still on them (the hero must not creep); jump on them.
- **Low hop platform** (1.2 units): even the shortest tap (about 1.4 units of rise) should clear it.
- **Full-jump platform** (5 units): needs a held jump; a tap (about 1.4 units) must fall short.
- **Too-high platform** (8 units): should be unreachable. By arithmetic a full jump rises about 6.0 units with the code's per-step gravity; the panel's apex reading shows the real number.

## What to look for when judging feel

- Jump height difference between a tap and a full hold (the tap should still give a small hop).
- Whether coyote time and the early-press buffer feel forgiving without feeling floaty.
- Run start and stop should feel instant (the original is digital, with no acceleration).
- Falling weight: gravity 60 and the fall cap 30 are the original's numbers.
- No sticking on walls or the cliff face, no jitter on slopes or plateau seams, no creeping when idle.

## PROVISIONAL config values

These five fields in `HeroConfig` were not confirmed from the original export and none of them affects this scene (the features arrive in later tasks):

1. `WallSlideSpeed` (original accelerates rather than using a fixed speed)
2. `WallJumpSpeedY` (assumed equal to JumpSpeed)
3. `PogoBounceSpeed` (best-guess match)
4. `HurtKnockbackX` (guessed recoil speed)
5. `HurtKnockbackY` (no value found)

## Notes

- The follow camera (`HeroTestCameraFollow`) is a placeholder; the real GameCamera comes in Task 11.
- `HeroController` takes its config and input by code injection, so `HeroDebugHud` does the wiring in this scene.
- Labels use the legacy `TextMesh`; if they render badly under the render pipeline, only the labels are affected.

## What to ignore when judging feel

- Slopes are rotated boxes that meet their plateau at a shared corner, so a tiny bump may be felt at the top seam. That is a property of this scratch geometry, not of the movement code.

## Replace later

`HeroDebugHud` injecting `Config` and `Input` into the hero is a scratch-scene shortcut. Task 11 (the real camera and room bootstrap) must replace it with a proper bootstrap. The HUD logs an error if its hero, actions or config reference is missing.
